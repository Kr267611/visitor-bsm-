Sabse zaroori faisle

  • Visitor ko app install nahi karnaWhatsApp ya SMS par link aur QR pass milega. Ek baar aane wala banda app download nahi karega.
  • Mobile app ek, roles doLogin ke baad Guard ko gate screen dikhegi, Employee ko approve aur invite screen.
  • Web app desk aur admin ke liyeReception, security aur HR ko badi screen par live list, reports aur settings chahiye.
  • Ek backend, ek databaseModular monolith. Is scale par microservices sirf kharcha aur complexity badhayenge.
  • Gate internet ke bina bhi chalegaQR digitally signed hoga, isliye guard app offline bhi verify kar sakti hai.
  • Har action ka recordKisne, kab, kaunse gate se kya kiya: yeh ek append-only log mein jayega, edit nahi hoga.

Database design

visits mein current status rehta hai, aur visit_events mein poori history. Visitor ek hi baar save hota hai, phone number se pehchana jata hai, isliye agli visit par details dobara nahi bharni.

visits

id, code, visitor_id, host_id, site_id, group_id, type, purpose, status, valid_from, valid_to, in_gate_id, out_gate_id, checked_in_at, checked_out_at, vehicle_no

Main table. Index: (site_id, status), (host_id, valid_from).

visit_events

id, visit_id, type, actor_id, gate_id, device_id, client_event_id UNIQUE, occurred_at, received_at, meta

Append-only audit log. Unique ID se offline sync mein duplicate nahi banega.

visitors

id, phone UNIQUE, name, company, photo_key, id_type, id_last4, consent_at, delete_after

Poora ID number kabhi save nahi hoga.

users

id, name, phone, email, role, department, site_id, delegate_id, is_active

Roles: guard, employee, reception, security, admin.

sites, gates

sites: id, name, address, timezone
gates: id, site_id, name

Shuru se rakhein. Baad mein doosri site add karna aasan rahega.

watchlist

id, phone, name, reason, added_by, active_until

Sirf security aur admin dekh sakte hain.

outbox

id, visit_id, channel, template, recipient, status, attempts, next_retry_at, provider_msg_id

Har notification ka record aur retry state.

devices

id, user_id, gate_id, fcm_token, last_seen_at, revoked_at

Guard ka phone kho jaye to yahin se block.

Deep dive: mushkil hisse

QR pass

QR mein sirf visit ID, site aur valid time hota hai, naam ya phone nahi. Server private key se sign karta hai (Ed25519). Guard app ke paas public key hoti hai, isliye bina internet ke bhi nakli QR pakda jata hai.

Offline gate

  • App aaj ke visits, watchlist aur photos cache rakhti hai.
  • Har scan phone mein clientEventId ke saath save hota hai.
  • Net aate hi /gate/sync. Same ID dobara aaye to server ignore karta hai.
  • Asli time occurred_at rehta hai, sync ka time received_at.

Notifications (outbox pattern)

Status change aur notification ki entry ek hi database transaction mein save hoti hai. Worker baad mein bhejta hai aur fail hone par exponential backoff se retry karta hai. Isse WhatsApp down hone par check-in nahi rukta, aur koi message gum nahi hota.

Approval timer

Walk-in banate hi BullMQ mein delayed jobs lagte hain: 90 second par reminder, 3 minute par backup person, 5 minute par reception ka call task. Host jawab de de to baaki jobs cancel. Yeh timings settings mein admin badal sakta hai.

Live screens

Desk dashboard aur guard screen WebSocket se update hote hain, site ke room ke hisaab se. Connection toote to app 30 second wali polling par aa jati hai.

Photos

App photo ko compress karke seedha storage par upload karti hai, signed URL se. Database mein sirf key rehti hai. Photo dekhne ke liye short-lived URL banta hai.

Security aur privacy

Yeh system logon ka naam, phone aur photo rakhta hai, isliye yeh features baad ke liye nahi chhodne.

Personal data lawDPDP Act 2023 ke hisaab se consent notice, data delete karne ka tareeka aur retention. Final wording company ke legal se confirm karwayein.

Scale ka hisaab

500 visits roz ke assumption par. Ek visit mein lagbhag 15 API calls aur 200 KB ki ek photo maani hai.

Iska matlab ek chhota server (2 vCPU, 4 GB) aur managed PostgreSQL kaafi hai. Asli khatra load nahi hai. Asli khatra gate ka rukna hai, isliye daily backup, restore test, aur offline mode par dhyan dena hai.

Build phases

Time ka andaza 2 se 3 developers ke liye hai. Scope final hone par hi pakka hoga.

Phase 1: MVP

Lagbhag 8 hafte
  • Login aur roles
  • Invite, walk-in, approval
  • Signed QR, check-in, check-out
  • Live desk dashboard
  • Push + SMS, audit log, consent

Phase 2: Gate ke liye pakka

Lagbhag 4 se 6 hafte
  • Offline mode aur sync
  • WhatsApp, badge printing
  • Watchlist, overstay alerts
  • Reports, emergency list
  • Auto-delete of old data

Phase 3: Jab zaroorat ho

Demand ke hisaab se
  • Self check-in kiosk
  • Contractor ke liye multi-day pass
  • HRMS se employee sync
  • Turnstile ya boom barrier
  • Multi-site analytics

System badhne par kya dobara dekhna hai

  • Doosri companies ko bechna ho: har table mein org_id aur data isolation.
  • Roz 10,000+ visits: reports ke liye read replica, workers alag server par, purane events ka partition.
  • Turnstile lagna ho: gate hardware ke liye alag service, kyunki uska response time aur reliability ki maang alag hai.

Aapse confirm karna hai

  1. Kitni sites aur gates hain, aur roz lagbhag kitne visitors aate hain?
  2. Aapki team kaunsi technology jaanti hai, aur kitne log banayenge?
  3. Data cloud par rakh sakte hain, ya company ke apne server par hi rakhna hai?
  4. Gate par kya hai: phone, tablet, badge printer, ya turnstile?
  5. Kya ID dekhna zaroori hai? Laptop ya vehicle entry bhi record karni hai?
  6. Kya sirf apni company ke liye hai, ya baad mein doosron ko bhi bechna hai?
